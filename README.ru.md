VibeDrop состоит из трёх компонентов, которые напрямую взаимодействуют в локальной сети по **WebSocket**. Интернет и облачные службы не нужны:

- **Приложение для Mac** (`desktop/`) — принимает текст и файлы, транслирует буфер обмена, работает через системное меню
- **Мобильное приложение** (`mobile/`, Android + iOS) — отправляет текст, изображения, видео и файлы, показывает временную шкалу истории
- **Home Vault** (`scripts/`) — домашний сервер для объединения истории с разных устройств, хранения оригиналов медиа и сбора журналов диагностики

## Обзор технической архитектуры

```
        ┌────────────────────────────┐      ┌────────────────────────────┐
        │   Mac 桌面端 × N (Tauri 2) │      │  手机端 × N (Tauri 2 Mobile)│
        │  ├ Axum HTTP/WS :9001      │◄────►│  ├ app.js  单文件前端       │
        │  ├ enigo 键盘模拟          │  WS  │  ├ lib.rs  16 个原生命令    │
        │  ├ arboard 剪贴板监听      │      │  ├ Kotlin  保活/播放器/剪贴板│
        │  ├ CGEventSource 活动上报  │      │  └ iOS     滚动锁(KVO)      │
        │  └ UDP/HTTP 发现应答       │      └──────────────┬─────────────┘
        └──────────────┬─────────────┘                     │
                       │              HTTP :8788           │
                       ▼                                   ▼
        ┌──────────────────────────────────────────────────────────┐
        │        Home Vault (家庭服务器, home-vault-receiver.py)     │
        │  跨设备历史合并 · 媒体原件仓(哈希去重+Range) · SSE 广播     │
        │  设备名公告板 · 探针日志回收 · 自我研究报告(SWR)            │
        └──────────────────────────────────────────────────────────┘
```

Три канала связи, все напрямую в локальной сети и без облака:

1. **Телефон ↔ Mac**: WebSocket (`:9001/ws`), передача текста, файлов, буфера и запросов активности после PIN-аутентификации;
2. **Все устройства → Home Vault**: HTTP (`:8788`), инкрементальная отправка истории, загрузка медиа и получение отчётов;
3. **Vault → клиенты**: постоянное SSE-соединение (`/api/events`), рассылка сразу после записи и пульс каждые 25 секунд.

## Подробно об основных процессах

### Умная карточка отправки «Отправлять за курсором»

1. Получив `activity_query`, приложение для Mac вызывает `CGEventSourceSecondsSinceLastEventType`
   и отвечает, сколько секунд прошло с последней активности клавиатуры или мыши (без разрешений и потоков — читается готовый системный журнал для заставки);
2. Телефон каждую секунду опрашивает все подключённые Mac и сравнивает **относительное время простоя** (разница часов компьютеров не влияет).
   Самый свежий Mac — тот, где курсор: Universal Control действительно передаёт события клавиатуры и мыши на компьютер с курсором, поэтому сигнал тесно связан с фактом;
3. Цель фиксируется в момент отправки текста, изображения или файла; нажатие индикатора переключает автоматический и ручной режимы.

### Обнаружение и сопряжение

Телефон одновременно сканирует двумя способами: UDP-рассылка + HTTP-проверка (`discover_desktops`). После обнаружения приложения для Mac начинается сопряжение по коду (на Mac появляется карточка подтверждения, обе стороны сверяют код); после одобрения устройство сохраняется и подключается автоматически.
Сохранённое имя устройства синхронизируется между телефонами через доску объявлений Vault (`/api/device-names`, ключ serverId, LWW).

### Текст и файлы

- Текст: действия `type` / `type_enter` заставляют Mac имитировать клавиатуру через enigo; Удалённый режим вместо этого использует
  `clipboard_text` (только запись в буфер, для средств удалённого управления вроде UU Remote);
- Файлы: протокол передачи по частям (begin/append/finish/cancel). На телефоне они попадают во входящие или Альбом,
  на Mac отправляются перетаскиванием/службой Finder. Вся цепочка несёт номер `transferId`, поэтому записи отправителя и получателя объединяются точно;
- Кнопки отправки не забирают фокус (mousedown preventDefault): клавиатура и голосовой ввод остаются активны после отправки,
  позволяя диктовать непрерывно без лишних действий.

### Синхронизация истории (инкрементально + в реальном времени)

- Каждое устройство хранит локальную историю + курсор отправки (`lastPushedEntryId`) и передаёт только прирост (измерено: 3 мс/188 Б на запись);
- Vault объединяет временную шкалу всех устройств (`/api/history/merged`). Обычно клиент получает 2 000 лёгких записей и один раз за сеанс глубоко загружает 10 000; событие SSE сразу обновляет данные;
- Одинаковые имена автоматически объединяются (новый случайный ID после переустановки — «прошлая жизнь» — включается в локальную идентичность); имя служит отображению, идентичность определяется отпечатком.

### Хранилище оригиналов

Оригиналы сохраняются по SHA-256 (`/api/media/upload`, потоковая передача + дедупликация, предел 2 ГБ). Любое устройство получает оригинал онлайн по хэшу (`/api/media/blob/<hash>`, Range-стриминг) — «утрачено локально ≠ утрачено везде».

### Проверочный зонд при запуске (чёрный ящик)

В начале `app.js` устанавливаются перехват window.onerror и точки probe(). Через 6 секунд после запуска или 1,5 секунды после ошибки отправляется POST в Vault `/api/client-log`, журнал сохраняется по устройствам. Чёрный или белый экран на реальном устройстве не нужно угадывать — причина видна в журнале.

## Практические уроки по платформам

### Различия движков WebView (важно)

| | Android | iOS | macOS |
|---|---------|-----|-----------|
| Движок | Chromium | **WKWebView** | **WKWebView (как в iOS!)** |
| `content-visibility: auto` | ✅ Системная виртуализация | ❌ Чёрный экран | ❌ Пустоты при прокрутке |
| Длинные списки | content-visibility | Виртуальная прокрутка JS | Установка фрагментами |
| Сегментация китайского `Intl.Segmenter` | ❌ Делит на отдельные знаки | ✅ Полный словарь | ✅ |

**Вывод: междвижковая сегментация китайского должна использовать серверный jieba; content-visibility разрешён только на Android.**

### iOS

- **Фиксированная компоновка**: прокрутка внешнего WKWebView отключена архитектурой оболочки (`isScrollEnabled=false` блокирует только жесты;
  WebKit программно прокручивает страницу при показе клавиатуры, поэтому нужно **наблюдать contentOffset через KVO и возвращать до отрисовки**;
  закреплённое «начало» — системная точка покоя `-adjustedContentInset`, а не (0,0)); блокировка устанавливается снова при каждом возврате на передний план;
- Правило упаковки: `cargo tauri ios build --export-method debugging`, не запускать напрямую через Xcode Run;
- Бесплатная подпись действует 7 дней с даты создания и требует автоматического продления.

### Android

- Настраиваемый WebChromeClient **обязан делегировать исходному клиенту** (onShowFileChooser и т. п.); полная замена отключает выбор файлов;
- Настоящая консоль: `adb logcat -d VibeDropConsole:I "*:S"`;
- Пять ошибок «Cannot redefine property» при запуске — безвредный шум от двойного выполнения внедрённого скрипта Tauri; расследовать их не нужно.

### Mac

- Эмуляция клавиатуры enigo работает в отдельном потоке; опрос буфера каждые 500 мс → broadcast channel → каждое WS-соединение;
- Внутреннее имя исполняемого файла Mac по-прежнему `voicedrop` (учтите при использовании pgrep).

## Языки (i18n)

Используется подход gettext: **ключом служит китайский оригинал**. `t('发送并回车')` ищет строку в словаре текущего языка, а при её отсутствии возвращает китайский оригинал (частичный перевод всегда можно выпустить). Переменные задаются заполнителями, например `t('已改名为 {name}', {name})`; склеивание строк запрещено.
Сейчас доступно 11 языков. Новый язык = один файл `locales/<lang>.json` + одна строка в таблице `i18n.js`.

- Проверка качества: `python3 scripts/i18n-check.py --strict` (покрытие ключей/целостность заполнителей);
- Проверка смысла: вручную прочитать 30 основных терминов каждого языка (машина не гарантирует семантику; см. `docs/i18n-规范.md`);
- В списке языков используются **самоназвания** с китайской и английской подсказкой произношения; языковые пакеты их не переводят.

## Сборка и развёртывание

```bash
# Android(需 cargo + Android SDK 于 PATH)
./scripts/deploy-android.sh          # 构建签名 APK + adb 安装启动

# macOS 桌面端
./scripts/deploy-desktop.sh          # 构建 + 本地自签 + 装入 /Applications
#   --skip-build --skip-icons        # 复用现成产物只重装(异机编译后拷贝场景)

# iOS(必须走 Tauri 管线)
cd mobile/src-tauri && cargo tauri ios build --export-method debugging
xcrun devicectl device install app --device <UDID> gen/apple/build/arm64/VibeDrop.ipa
```

**Два правила**:

1. После изменения app.js / index.html / style.css / i18n.js / locales/ в `mobile/src/`
   **обязательно скопировать в `desktop/static/`** (мобильная браузерная версия настольной HTTP-службы);
2. **Две сборки Tauri нельзя запускать параллельно** (общий локальный IPC-канал конфликтует), только последовательно.

## Публикация на GitHub

Отправка тега `v*` запускает `release.yml`: автоматически собираются подписанный APK + dmg macOS и публикуется GitHub Release;

## Анализ сообщений и отчёт о частоте слов

Анализирует собственный корпус истории Home Vault: сегментацию и частоту слов, любимые выражения, частые фразы, изменение тем по месяцам (TF-IDF) и активность отправки (столбчатые графики по часам/дням с просмотром подробностей жестом). Автономный HTML-отчёт создаётся полностью локально, данные никуда не отправляются.

**Прямо в приложении**: История → карточка «Анализ сообщений» → Открыть полный отчёт (конечная точка Home Vault `/report/self-study`, мгновенное открытие из SWR-кэша, фоновый пересчёт после истечения, `?refresh=1` запускает принудительно).

Можно создать и вручную:

```bash
python3 -m venv .venv && .venv/bin/pip install jieba
.venv/bin/python scripts/message-self-study.py http://<你的vault地址>:8788
```

Отчёт сохраняется в `~/Downloads/`. Договор по многоязычной реализации находится в `docs/i18n-规范.md`.
